# 首页模式文案

## 在云控制台修改

集合名：`modeContent`

每个模式固定一条记录。日常只需要编辑：

- `title`：卡片标题，最多 40 个字符；
- `description`：卡片介绍，最多 120 个字符。

不要修改 `_id` 和 `modeKey`。它们是模式的稳定身份，不是展示文案。客户端进入首页
时会读取云端内容并缓存；云端不可用或字段留空时，自动使用代码内置文案。

| `_id` / `modeKey` | 当前模式 |
| --- | --- |
| `artist` | 歌手默契挑战 |
| `album` | 专辑默契挑战 |
| `top9` | 同担 Top 挑战 |
| `songTournament` | 决战歌曲之巅 |
| `tree` | 圣诞树推歌 |
| `theme` | 主题推歌 |
| `rainBox` | 雨水一盒 |
| `lyrics` | 歌词分享 |

## 与二级菜单解耦

`modeContent` 只管理文案，不保存路由、点击函数、显示层级或父菜单。以后建立二级菜单时，
另建 `modeNavigation` 集合，建议字段为：

- `modeKey`：关联 `modeContent`；
- `menuKey`：所在菜单；
- `parentKey`：父菜单；
- `order`：同级排序；
- `visible`：是否显示。

页面能力和允许跳转的地址仍由代码白名单管理。这样移动菜单只改导航数据，编辑文案只改
内容数据，二者不会互相覆盖；新增一种从未发布过的功能仍然需要发版。
