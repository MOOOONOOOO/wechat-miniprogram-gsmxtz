# “雨水一盒”视频托管与缓存

## 当前实现

- 四段 MP4 不放进小程序代码包。
- 云存储或 CDN 是源文件，用户本地缓存是播放副本。
- 小程序启动后会在后台按时间线 1 → 2 → 3 → 写信顺序下载；进入页面时直接复用这次预取。
- 下载完成后保存到 `wx.env.USER_DATA_PATH`，以后直接使用本地文件。
- 文件名带 `MEDIA_VERSION`；版本变化时先下载新文件，全部成功后清理旧版本。
- 下载或缓存失败时会保留重试入口，不会进入半加载的动画状态。

四段素材会作为一个版本一次性持久缓存。若之后素材继续增长，不建议无限缓存，应增加 30 天未使用清理或 LRU 上限。

## 推荐托管：微信云开发存储

项目已经初始化 `wx.cloud`，因此最省配置的方案是：

1. 在微信开发者工具的“云开发 → 存储”中建立 `rain-box/2026-07-26-v1/`。
2. 上传：
   - `timeline-1.mp4`
   - `timeline-2.mp4`
   - `timeline-3.mp4`
   - `timeline-4.mp4`（写信动画）
3. 复制四个文件的 `cloud://` fileID。
4. 填入 `miniprogram/config/rainBoxMedia.js` 对应的 `source`。

缓存工具同时支持 HTTPS CDN 地址；使用 CDN 时，需要把域名加入小程序的 `downloadFile` 合法域名。

## 视频编码建议

正式上传前建议重新导出一套移动端版本：

- MP4 容器；
- H.264 视频；
- AAC 音频，或完全移除音轨（当前动画静音播放）；
- 720p 通常足够；
- 添加 `faststart`，让 MP4 元数据位于文件开头；
- 服务端返回正确的 `Content-Type: video/mp4`；
- CDN 支持 Range 请求。

移动端 720p 版本通常能显著减少首次下载体积，进入体验会更快。
